# riskell: built-in features an extension cannot replace or extend today

Status: an inventory, not a plan. Every atom is a package on the kit; everything below is what still sits in the application. The gaps worth
closing first are the ones that block a whole class of extensions: the window-manager backends, the notch and its wings, the workspace overview
and the gesture/behaviour route. See `docs/ROADMAP.md`.

Scope: every feature of riskell that is not an atom package in `Packages/`. Paths are relative to the riskell-public repository. Line counts are approximate (`wc -l`). Every row was taken from the files named in it. Read in full: the app's main, Registry, Atoms, ExtensionHost, Extensions/ (Extension, GesturesExtension, ScrollGuard, GestureConflicts), Popout, Layout, Bars, Wings, WingFit, Display, Scale, Spacing, Frame, Store, Windows, Sky, SpaceWatch, EditBackdrop, SettingsCards, HotKey, InstanceLock, Needs, Gaps, NoWM, WindowManager, AppConfig, ConfigWatcher, EventSocket, Omni, Compat, NowPlaying, `Packages/clock`, nowplaying.c and its header, Themes/Theme and ThemePicker, the Gaps and Needs services, and the kit surface in `docs/KIT-API.md`. Read in part: EditMode (the panel and the atom editor), ChatCard, Overview, OverviewView, Touch, Sys, Pills, Capture, Yabai, AeroSpace, CommandWM, `Sources/riskell-ext/main.swift`. Skimmed by header and function list only: `Sources/riskell-setup/` (23 files) and `scripts/`; the generated `Themes/Schemes.swift` was read by its header. Where the code did not settle a question the row says "unclear".

Legend. **Extensible today**: yes = an extension (or a config file) does it with no change to riskell; partly = some part is open through a documented hook; no = host code only. **Size** of the change needed to open it: S = a few lines in the kit or the host; M = a new kit API plus a host seam; L = a new subsystem or a rewrite of host code.

## Order I would open them in

1. `Sources/riskell/ExtensionHost.swift`: the seam where packages become atoms, feeds and hooks, so everything else is reached through it.
2. `Sources/riskell/Registry.swift` and `Atoms.swift`: the atom list and how each atom is drawn.
3. `Sources/riskell/Store.swift` with `FeedBridge` in `ExtensionHost.swift`: the state that exists and the five values that are offered.

5. `Sources/riskell/Services/WindowManager.swift` and `CommandWM.swift`: the backend seam, and the one backend already open through config.
6. `Sources/riskell/Popout.swift`: how a card is hosted, which decides what an atom can ask for.
7. `Sources/riskell/Layout.swift` and `Bars.swift`: placement data and bar drawing.
8. `Sources/riskell/Services/AppConfig.swift` and `ConfigWatcher.swift`: the file an extension can read and the reload path.

11. `Sources/riskell/Services/EventSocket.swift` and the command table in `main.swift`: the scripting surface.
12. `Sources/riskell/EditMode.swift` and `SettingsCards.swift`: the editor and the EXTENSIONS card.

## Things that are host-owned on purpose

- **The popout window.** One panel for every card keeps placement, stacking and dismissal consistent.
- **The display geometry and the scale.** Extensions lay out in design units and never see a pixel, a screen or a scale (the extension guide, section A).
- **Bar windows and their levels.** Extensions may not open windows, and the levels depend on the macOS version.
- **Private system interfaces** (SkyLight, MultitouchSupport, MediaRemote). They change between macOS versions, so each is looked up at run time in one place.
- **The event tap and its Accessibility permission** (scroll guard). It is an input capability, kept behind a closed list until a review policy exists.
- **The Store.** One writer per value; extensions get values through feeds.
- **The workspace overview.** It owns a full-screen panel, captures and gestures.
- **The theme contrast floors.** They are what keeps every extension readable on every theme.
- **The compatibility checks.** They check riskell's own dependencies against the versions it was verified with.
- **The gap writer and the manager settings.** Writing another program's settings file needs one owner.
- **The instance lock.** It stops two processes from fighting over the socket, the trackpad and the gaps.
- **The config writer and the layout drop rules.** One writer for `config.json`, and one set of rules for every bar.
- **The installer and the launch job.** They write the user's files and the system's login registration.
